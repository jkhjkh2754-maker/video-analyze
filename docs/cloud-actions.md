- 워크플로는 수동 실행만 지원하며 자동 재시도·일정 실행을 등록하지 않았습니다. 실제 영상 확보가 선행되지 않아 전체 분석 패키지 생성 연결은 진행하지 않았습니다.

이 워크플로는 수동 실행만 지원합니다. 코드 push·PR·일정으로 자동 실행하지 않습니다. 표준 `ubuntu-24.04` 실행기에서 무료 도구를 설치하고 실제 영상 파일을 받아 FFprobe로 확인합니다. 비공개 저장소에서는 job 전체를 건너뜁니다. 추가 저장 비용을 방지하기 위해 아티팩트 업로드와 캐시를 사용하지 않고, 이번 시험 결과는 실행 로그와 job summary에 표시합니다.

## 실행

1. 저장소 공개 전환 전에 기존 코드·문서·커밋에 비밀정보나 공개하면 안 되는 자료가 없는지 확인합니다. 이 워크플로가 저장소 공개 여부를 변경하지는 않습니다.
2. 기본 브랜치에 `.github/workflows/youtube-download-probe.yml`과 `scripts/cloud_download_probe.py`가 있어야 수동 실행 목록에 표시됩니다.
3. Actions → YouTube download probe → Run workflow에서 이용 권한이 있는 단일 영상 URL을 입력합니다.
4. 완료 후 job summary와 Download and verify actual media 단계의 JSON 출력에서 검증 결과를 확인합니다. 무인증 모드는 URL을 가린 실패 로그도 표시하며, 쿠키 인증 모드에서는 원시 출력을 억제합니다.

## 선택적 Secrets 인증 — 값 등록 전 준비 완료

이 기능은 본인 계정의 정상 세션을 선택적으로 전달하는 기능입니다. 쿠키 값은 개발자나 채팅에 전달하지 않고 GitHub UI에 직접 등록합니다. 준비 과정에서 실제 쿠키를 요청·조회·저장하지 않았으며, 인증 다운로드도 실행하지 않았습니다.

1. 저장소 Settings → Secrets and variables → Actions → New repository secret을 선택합니다.
2. 이름을 **YOUTUBE_COOKIES**로 지정하고 본인이 준비한 YouTube 전용 Netscape 형식 쿠키 파일 내용을 Value에 입력합니다. Base64나 JSON이 아닌 파일 내용 전체를 입력합니다. 48KiB 이하, 첫 줄 `# Netscape HTTP Cookie File` 또는 `# HTTP Cookie File`, 탭으로 구분한 7개 열이어야 합니다. YouTube 이외 도메인의 쿠키가 섞인 파일은 거절합니다. 브라우저 전체 쿠키를 등록하지 마세요.
3. 수동 실행 화면의 **use_cookies**를 켜면 해당 Secret을 사용합니다. 기본값은 꺼짐이며, 꺼진 상태에서는 Secret이 전달되지 않습니다. 이 준비 단계에서는 등록 또는 실행이 자동으로 수행되지 않습니다.

`YOUTUBE_COOKIES`는 다운로드 단계에만 환경변수로 전달됩니다. Python이 이를 읽은 뒤 환경변수에서 제거하므로 yt-dlp 자식 프로세스에는 값 자체를 상속하지 않습니다. RUNNER_TEMP 아래 0700 임시 디렉터리 안에 0600 쿠키 파일을 만들고, 명령줄에는 값 대신 파일 경로만 전달합니다. 성공·실패·시간 초과 시 파일을 삭제하며 별도 `if: always()` 정리 단계도 실행합니다. 실행기 강제 종료 때 정리 단계가 실행된다는 보장은 없고, 이 경우 호스팅된 일회성 실행기의 폐기에 의존합니다. 파일 삭제는 보안 삭제를 의미하지 않습니다.

인증 모드에서는 yt-dlp stderr를 폐기하고 stdout은 ID·길이 JSON 파싱에만 사용합니다. 원시 오류·예외·제목·쿠키 이름·경로를 결과 파일이나 공개 로그에 기록하지 않습니다. 원본 info.json도 생성하지 않습니다. GitHub의 자동 마스킹에만 의존하지 않습니다. Secret 누락·잘못된 형식은 yt-dlp 실행 전에 실패하며, 오류의 `stage=authentication_setup`으로 구분합니다. `stage=download`이면 다운로드 실행 중 실패, `stage=verification`이면 실제 파일 검증 중 실패입니다.

기능 추가 후 전체 로컬 테스트 **23개 통과**, YAML 수동 트리거·기본 opt-out 검증 통과. 실제 인증정보 대신 명백한 가짜 테스트 값을 사용해 권한 0600/0700, 자식 환경변수 제거, 원시 출력·시간 초과 예외에 가짜 값이 포함돼도 공개되지 않음, 성공·실패·시간 초과 뒤 삭제, Secret 누락·타 도메인 거절을 검증했습니다. 실제 계정 인증과 YouTube 다운로드 성공 여부는 미검증입니다.

공개 저장소의 쓰기 권한을 가진 사람은 워크플로를 수정할 수 있으므로 신뢰할 수 있는 사람에게만 쓰기 권한을 부여하세요. 이 워크플로는 pull_request나 외부 입력으로 자동 실행되지 않지만, GitHub Secrets가 악의적인 워크플로 코드로부터 인증정보를 보호해 주지는 않습니다.

`download_verified`는 실제 영상 파일 존재·크기·영상 스트림·원본 대비 길이를 검증한 경우에만 기록합니다. 실패 또는 필터로 건너뛴 경우 성공으로 보고하지 않습니다. 본편이 다운로드되더라도 자막 다운로드 오류로 전체 명령이 실패하면 실패로 표시합니다.

## 범위와 비용

- 수동 실행, 동시 1개, 실행당 15분 제한, yt-dlp 하위 프로세스 11분 제한.
- 1시간 이하의 완료된 영상, 720p 이하 형식, 형식별 2GB 제한. 용량 정보가 없는 형식은 미리 크기를 확정할 수 없습니다.
- 계정 쿠키는 위의 선택적 Secret 설정을 켠 경우에만 사용합니다. 외부 프록시·PO token·유료 API는 사용하지 않습니다. 접근 제한 시 실패를 기록하고 자동 재시도하지 않습니다.
- 원본 영상과 보고서 파일은 러너 임시 디스크에만 둡니다. Git 커밋과 아티팩트에 포함하지 않습니다. 공개 로그에는 검증 JSON만, 무인증 모드의 실패 때만 URL을 가린 오류 로그를 추가 출력합니다.
- 공개 저장소에서는 실행 로그도 공개됩니다. 공개하면 안 되는 영상 URL을 입력하지 마세요.
- 공개 저장소의 표준 러너 무료 컴퓨팅 설명: https://docs.github.com/en/actions/concepts/billing-and-usage
- 실제 다운로드가 성공한 후에 전사·프레임·분석 ZIP 전체 처리 연결을 진행합니다. 현재 단계는 다운로드 시험입니다.
