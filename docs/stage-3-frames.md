# 3단계 프레임 추출

2026-11-07 UTC. 사용자 승인 범위에서 구현했다. 4단계는 승인되지 않았으며 시작하지 않았다.

## 실행

추가 Python 패키지 없이 Python 3.12와 FFmpeg를 사용한다. 로컬 영상 또는 2단계에서 확보한 파일 경로를 명시한다.

```bash
python frames.py downloads/<실행폴더>/video.mkv
python frames.py /path/to/local.mp4 --interval 10 --scene-threshold 0.3 --similarity-threshold 0.03 --max-images 120 --output outputs
python -m unittest discover -s tests -v
```

기본 간격 10초, 장면 변화 임계값 0.3, 유사도 차이 임계값 0.03, 최대 이미지 수 120개다. 각 실행은 별도 `outputs/frames-…` 디렉터리를 생성한다. 결과는 640×360 PNG와 `frames.json`이다. 종횡비는 유지하고 여백을 추가한다. 이미지·타임스탬프는 추출된 영상의 첫 PTS를 0초로 정규화한 기준이며 자막 시간축 통합은 수행하지 않는다.

첫 프레임, 10초 단위 시간 구간에 처음 들어온 프레임, FFmpeg scene 점수가 임계값을 넘는 프레임을 후보로 삼는다. 따라서 10초가 정확히 존재하지 않는 가변 프레임률 영상은 해당 시각 이후 첫 프레임을 선택한다. 모든 입력 프레임을 디코딩해 장면 전환을 검출하므로 긴 영상에는 시간이 걸린다.

각 후보의 64×36 RGB 샘플을 이전에 채택한 모든 이미지와 비교한다. 정규화한 평균 절대 색상 차이가 0.03 이하면 유사·중복으로 제거한다. 기본 임계값은 조절 가능하며 의미상의 중복을 판별하는 모델이 아니다. 조명·자막·작은 글자 변화가 누락되거나 유사 장면이 남을 수 있다. 간격 후보도 중복이면 제거하므로 결과에 반드시 10초마다 이미지가 남는 것은 아니다.

최대 수에 도달하면 디코딩을 중단한다. `limit_reached=true`는 상한에 도달했다는 뜻이며, 뒤에 추가로 유효한 이미지가 존재한다는 판정은 아니다. 앞부분 우선 방식으로, 전체 영상에서 균등 배분하지 않는다.

`frames.json`에는 설정, 상태, 원본 파일 경로, 파일명, 초 단위 타임스탬프, `HH:MM:SS.mmm`, 중복 제거 수와 최대 수 도달 여부를 기록한다. 오류 시 `failed`와 오류 메시지를 남기며, 부분 생성 파일이 남을 수 있다. 출력에는 로컬 절대 경로가 들어가므로 공유 전 확인한다. CLI 종료 코드 0=추출 성공, 1=처리 실패, 2=입력 오류다.

## 검증과 미완료 구분

실제 FFmpeg로 임시 합성 영상을 생성하여 테스트했다. 2단계 기존 테스트 8개와 3단계 테스트 6개, 총 14개가 통과했다.

- 움직이는 25초 영상: 기본 주기 0·10·20초 확인.
- 빨강→흰색→빨강→파랑의 16초 영상: 0·4·12초 이미지 유지, 8초 반복 장면 제거 확인.
- 최대 2개 제한, 유사도 임계값 적용, PNG 파일 및 JSON 타임스탬프 일치 확인.
- 잘못된 옵션 거부와 손상 영상의 실패 결과 기록 확인.

합성 파일은 임시 디렉터리에서 생성하고 테스트 종료 시 삭제했다. 테스트의 다운로드 호출은 기존 대역을 사용하므로 YouTube 다운로드 성공을 증명하지 않는다.

현재 환경은 unrestricted/enforced이지만 YouTube 연결이 프록시 CONNECT 403으로 차단됐다. [네트워크 검증](current-network-verification.md) 참조. **실제 YouTube 다운로드 및 2→3단계 원격 통합 검증은 미완료**다. 이번 작업에서는 차단된 다운로드를 반복하지 않았다. 네트워크 복구 후 2단계로 확보한 실제 영상 파일을 `frames.py`에 전달해 통합 검증해야 한다.

전사, 자막과 이미지 결합, 분석 패키지, ChatGPT 전송 등 4단계 이상의 기능은 수행하지 않았다.
